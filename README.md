# Каталог фильмов — CRUD API

Учебное приложение на FastAPI для хранения каталога фильмов в SQLite.
Позволяет добавлять, получать, редактировать и удалять фильмы, искать их по названию,
фильтровать по жанру, году и рейтингу, сортировать и получать данные постранично.
Входные данные проверяет Pydantic, а основные ограничения продублированы в БД.

## Возможности

- Создание фильма и получение фильма по идентификатору.
- Полная замена через PUT и частичное обновление через PATCH.
- Удаление с ответом 204, обработка отсутствующего фильма с ответом 404.
- Фильтрация, сортировка и пагинация списка.
- Защита от дублей «название + год»: ответ 409 и откат транзакции.
- Автоматическая документация Swagger UI и ReDoc.
- Версионирование схемы через Alembic; тесты CRUD и проверок данных.

## Технологический стек

Python 3.10+, FastAPI 0.115.6, Uvicorn 0.34.0, SQLAlchemy 2.0.36,
SQLite, Alembic 1.14.0, Pydantic 2.12.5.
Для проверки: pytest 8.3.4 и HTTPX 0.28.1. Работа с БД синхронная;
маршруты объявлены через `def`, сессия БД предоставляется через зависимость `get_db`.

## Быстрый старт

```bash
git clone https://github.com/Sanik1yt/movie-catalog-api.git
cd movie-catalog-api
python -m venv .venv
```

Активируйте окружение в Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

Или в Linux/macOS:

```bash
source .venv/bin/activate
```

Установите зависимости, примените миграции и запустите сервер из корня проекта:

```bash
python -m pip install -r requirements.txt
python -m alembic upgrade head
python -m uvicorn app.main:app --reload
```

Адрес сервера: `http://127.0.0.1:8000`.
Swagger UI: `http://127.0.0.1:8000/docs`.
ReDoc: `http://127.0.0.1:8000/redoc`.
Спецификация OpenAPI: `http://127.0.0.1:8000/openapi.json`.

По умолчанию создаётся файл `movies.db` в рабочем каталоге. Сервер самостоятельно
не создаёт таблицы: перед первым запуском обязательно выполните миграции.
Файл БД, окружение и секреты не включаются в репозиторий.

Для другого SQLite-файла задайте одну и ту же переменную `DATABASE_URL`
при миграциях и запуске приложения. Например, в PowerShell:

```powershell
$env:DATABASE_URL = "sqlite:///./catalog.db"
python -m alembic upgrade head
python -m uvicorn app.main:app --reload
```

В Linux/macOS: `export DATABASE_URL=sqlite:///./catalog.db`.

## Основные эндпоинты

| Метод | Адрес | Назначение | Успех |
|---|---|---|---:|
| GET | `/` | Информация о приложении | 200 |
| POST | `/movies` | Добавить фильм | 201 |
| GET | `/movies` | Получить список с фильтрами | 200 |
| GET | `/movies/{movie_id}` | Получить один фильм | 200 |
| PUT | `/movies/{movie_id}` | Полная замена полей фильма | 200 |
| PATCH | `/movies/{movie_id}` | Изменение только переданных полей | 200 |
| DELETE | `/movies/{movie_id}` | Удалить фильм, тело ответа пустое | 204 |

Пример тела POST или PUT:

```json
{
  "title": "Arrival",
  "year": 2016,
  "genre": "Sci-Fi",
  "rating": 8.0,
  "description": "История первого контакта"
}
```

Ответ дополнительно содержит числовой `id`. PATCH принимает, например,
`{"rating": 8.5}`. Неуказанные поля PATCH сохраняются; явный `null` запрещён.
При PUT обязательны название, год и жанр; неуказанные рейтинг и описание
получают значения 0.0 и пустую строку.

Пример запроса через curl (Linux/macOS):

```bash
curl -X POST http://127.0.0.1:8000/movies \
  -H 'Content-Type: application/json' \
  -d '{"title":"Arrival","year":2016,"genre":"Sci-Fi","rating":8.0}'
curl 'http://127.0.0.1:8000/movies?genre=Sci-Fi&sort_by=rating&order=desc'
```

В Windows можно выполнить те же операции в Swagger UI через **Try it out**.
Некорректные данные дают 422, неизвестный id — 404, дубликат — 409.

## Фильтрация и сортировка

GET `/movies` принимает параметры, которые можно комбинировать:

| Параметр | Значение |
|---|---|
| `title` | Подстрока названия; символы `%` и `_` экранируются |
| `genre` | Точное совпадение жанра с учётом регистра |
| `year` | Точный год, 1888–2100 |
| `min_rating` | Минимальный рейтинг, 0–10 включительно |
| `sort_by` | Только `id`, `title`, `year`, `rating`; по умолчанию `id` |
| `order` | `asc` или `desc`; по умолчанию `asc` |
| `offset` | Число пропускаемых записей, от 0 |
| `limit` | Размер страницы 1–100, по умолчанию 20 |

Пример: `/movies?year=2016&min_rating=8&sort_by=rating&order=desc&limit=10`.
При равных значениях поля сортировки порядок стабилизируется по id.
Пустой результат фильтрации — `[]`. Поиск по названию использует SQLite LIKE;
не следует рассчитывать на полноценное регистронезависимое сравнение Unicode.

## Модель данных

Одна таблица `movies`:

| Поле | Тип | Правила |
|---|---|---|
| `id` | INTEGER | Первичный ключ, назначается БД |
| `title` | VARCHAR(200) | Непустое название, 1–200 символов |
| `year` | INTEGER | Год выпуска, 1888–2100 |
| `genre` | VARCHAR(50) | Непустой жанр, 1–50 символов |
| `rating` | FLOAT | Рейтинг от 0 до 10, по умолчанию в API 0.0 |
| `description` | TEXT | Описание до 2000 символов, по умолчанию в API пустая строка |

Строки входных моделей очищаются от пробелов по краям. Лишние поля запросов запрещены.

## Ограничения базы данных

- Все поля NOT NULL.
- Уникальная пара `(title, year)`; одинаковое название разных лет допустимо.
- CHECK для года, рейтинга, длины названия, жанра и описания.
- Первичный ключ `id`; индексы `ix_movies_title`, `ix_movies_year`, `ix_movies_genre`.
- Длина строк в SQLite обеспечивается CHECK, а не самим обозначением VARCHAR.
- Сравнение уникальности названий регистрозависимое; `Arrival` и `arrival` различаются.
- Внешних ключей нет: каталог состоит из одной таблицы.
- Значения рейтинга и описания по умолчанию задаёт API/ORM, а не SQL server default.

## Проверка и миграции

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
python -m alembic current
```

Тесты используют отдельную БД в памяти и не затрагивают `movies.db`.
Проверяются CRUD, валидация, дубликаты с откатом, фильтрация, сортировка,
пагинация, запрещённый null и отсутствующие записи.
Для разработки новой схемы: `python -m alembic revision --autogenerate -m "описание"`,
проверьте созданный файл и выполните `python -m alembic upgrade head`.

Это локальный учебный API: авторизация и публичное развёртывание в текущий проект не входят.
